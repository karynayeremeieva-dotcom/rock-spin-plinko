# Rock Spin · Plinko

[![CI](https://github.com/morch123/rock-spin-plinko/actions/workflows/ci.yml/badge.svg)](https://github.com/morch123/rock-spin-plinko/actions/workflows/ci.yml)

Plinko для Telegram Mini App в стиле рок-клуба. Только фронтенд: результат каждого шарика считает заглушка сервера `src/api/plinko.ts`, демо-баланс 1 000 RC.

## Запуск

Нужен Node 20.19+. Для `perf` и `e2e` — установленный Google Chrome.

```bash
npm ci
npm run dev        # http://localhost:5173
npm run check      # типы, ESLint, Prettier, актуальность таблиц, юнит-тесты
npm run e2e        # чек-лист приёмки через интерфейс в Chrome (--url=… для выложенной версии)
npm run perf       # бандл, первая отрисовка, FPS при 1/10/50 шариках
npm run perf:soak  # 10 минут авто-режима: память, DOM, FPS
npm run deploy     # проверки и сборка закоммиченного кода → ветка gh-pages
```

`npm run gen:multipliers` пересчитывает таблицы для 9–11 и 13–15 рядов. CI на каждый пуш прогоняет `check`, сборку и `e2e`.

## Стек и структура

React 18, TypeScript (strict, без `any`), Vite, Vitest, ESLint, Prettier. Доска — **Canvas 2D** без игровых движков, шарики не DOM-элементы. Других зависимостей во время работы нет, кроме двух самохостящихся шрифтов (Inter и Oswald).

```
src/
  api/plinko.ts      заглушка сервера: play({ bet, rows, risk }) → { id, path, bin, multiplier, payout }
  core/              логика без React и Canvas: деньги, RNG, таблицы и RTP, ставки,
                     авто-режим, движок игры, сохранение, симуляция
  board/             Canvas: геометрия, траектория по path, спрайты, рендерер, два корпуса доски
  ui/                React: шапка, доска, панель ставки, шторки, тур «Как играть», большой выигрыш
  dev/DevPanel.tsx   панель ?dev=1 (отдельный чанк, игроку не загружается)
  audio/sound.ts     звуки через Web Audio
  platform/          Telegram WebApp
  i18n/              RU / EN
  config/multipliers.json   27 таблиц коэффициентов
scripts/             генератор таблиц, замеры, e2e, деплой
```

## Главные решения

**Результат решается до анимации.** «Бросить» вызывает `play()`: заглушка делает `rows` выборов «влево/вправо» через `crypto.getRandomValues`, отвечает через 100–300 мс и возвращает путь, ячейку, коэффициент и выплату. Интерфейс не знает, как получен результат. Для настоящего сервера меняется только `play`.

**Анимация проигрывает известный путь.** Физики нет, потому что она не гарантирует попадание в нужную ячейку. Шарик прыгает параболами от штырька к штырьку ровно по `path`, случайны только мелочи вроде высоты отскока. Тест на 500 бросках при 8 и 16 рядах проверяет, что шарик всегда приземляется в ячейку из ответа.

**Деньги — целые сотые.** `100 000 = 1 000.00 RC`, выплата = `floor(ставка × коэффициент в сотых / 100)`, без дробей. Ставка списывается в момент нажатия, ещё до ответа сервера, поэтому быстрые клики и авто-режим не уводят баланс в минус. Выигрыш зачисляется, когда шарик долетает. Тесты сверяют: `начальный − ставки + выплаты = баланс`.

**Рендер дешёвый.** Штырьки нарисованы в отдельный слой, шарики и ячейки — готовые спрайты, кадр — это копирование картинок. Цикл отрисовки работает, только пока что-то движется. В свёрнутой вкладке полёт и авто-режим стоят на паузе, после возврата шарики долетают, и деньги сходятся.

**Два дизайна доски.** Основной — корпус V-образной электрогитары на сцене под прожекторами: штырьки-струны дрожат от ударов. Второй — минималистичный: обсидиановый треугольник в хромированной фаске с хромированными шариками вместо штырьков, на графитовом фоне. У каждого корпуса своя разметка поля и полки (`src/board/cabinet.ts`), пирамида подстраивается под неё. Тесты проверяют раскладку обоих дизайнов на всех числах рядов.

## Таблицы коэффициентов

Все 27 таблиц (8–16 рядов × Low/Medium/High) лежат в `src/config/multipliers.json`. Для 8, 12 и 16 рядов взяты значения из задания. Для остальных их строит `scripts/generate-multipliers.mjs`: смешивает соседние таблицы в логарифмах, масштабирует к RTP 99%, округляет до «ценовой лестницы» (0.1 до 10×, целые до 100×, десятки выше) и подгоняет симметричные пары ячеек, пока RTP не станет 99% ± 0.05%. Итог: RTP всех таблиц от 98.906% до 99.116%. `npm run check` падает, если JSON разошёлся со скриптом.

## Панель `?dev=1`

Кнопка DEV слева вверху. Выбор рядов и риска, таблица с редактируемыми полями (по умолчанию правка симметричная), шанс и вклад каждой ячейки и RTP таблицы на лету. Предупреждения о несимметричности, ошибках ввода и RTP вне 98.8–99.2%. Кнопки «Применить», «Сбросить к конфигу», «Скачать JSON». Симуляция 100 000 бросков через тот же код, что у заглушки, показывает фактический RTP против теоретического за доли секунды.

## Замеры

`npm run perf`: продакшн-сборка в Chrome 157, телефон 390×844 @2x, **CPU замедлен в 4 раза**. 12 ноября 2026, дизайн «Гитара».

| Что | Требование | Результат |
|---|---|---|
| JS-бандл, gzip | ≤ 300 КБ | **73 КБ** + 2.5 КБ панель `?dev=1` |
| Первая отрисовка, Fast 4G | < 2 с | **0.41 с**, игра готова за 0.72 с |
| FPS при 1 / 10 / 50 шариках | 60 / 60 / ≥ 50 | **60.6 / 60.2 / 60.3** |
| 10 минут авто, интервал 150 мс | без роста памяти и замедления | 3 787 шариков, куча 2.7–4.2 МБ без тренда, DOM 274–321 узел, FPS 60.4 → 60.3 |

Картинки — WebP, грузятся после первого кадра. Фон «Минимала» нарисован в CSS. Звуки синтезируются, файлов нет. Пока грузится JS, виден скелетон. Замедление CPU на Mac — не то же, что средний Android, на реальном Android я не мерил.

- **`npm run e2e`** — 22 проверки чек-листа 8.2 через интерфейс в Chrome: вёрстка без прокрутки на 360×640, 390×844 и 1440×900 для обоих дизайнов, RU/EN, Пробел, сохранение после перезагрузки, сходимость баланса, 300 быстрых кликов, панель `?dev=1` с симуляцией, пустая консоль. Свой скрипт на puppeteer, чтобы не скачивать браузер.
- **Вручную** — Safari и Telegram на iPhone.

## Telegram

В Telegram игра вызывает `ready()` и разворачивается на весь экран (Bot API 8.0+, иначе `expand()`). Ещё она отключает сворачивание свайпом, подстраивает цвета шапки и учитывает safe-area Telegram. Есть вибрация при броске и крупном выигрыше, подтверждение закрытия, пока летят шарики, а системная «Назад» закрывает шторки. Вне Telegram всё это молча пропускается. Подключение: @BotFather → Mini Apps → Main App и Menu Button со ссылкой на сайт.

## Как я понял неоднозначные места

- **Блокировка рядов и риска** — пока хоть один шарик ждёт ответа или летит и всё время авто-режима. Ставку менять можно всегда.
- **Профит сессии авто** — ставки в момент броска, выплаты в момент приземления, то есть ровно то, что игрок видит в балансе. «Стоп при выигрыше ≥ Z×» срабатывает по одному шарику.
- **«Стоп» в авто** сразу прекращает выпуск, летящие шарики долетают и платят.
- **Быстрые суммы 1/5/10/50** ставят ставку, а не прибавляют. `×2` и `Max` ограничены балансом и 1 000 RC.
- **Перезагрузка во время полёта**: результат уже решён, поэтому летящие шарики засчитываются, а ставки без ответа возвращаются.
- **Сбой сервера**: ставка возвращается, появляется сообщение, авто останавливается.
- **Большой выигрыш**: от 10× «Крупный», от 50× «Мега», от 250× «Легендарный». Игру не блокирует.
- **«Как играть»** — не модалка с картинками, а тур по настоящему экрану с бесплатными пробными шариками. Открывается сам при первом входе, повторно — из меню.
- **История** — последние 50 ставок, страницами по 10.
- **Звуки** синтезируются через Web Audio вместо ogg/mp3: ноль загрузок и нет «треска» при 50 шариках.
- **Числа**: RU `1 000.00`, EN `1,000.00`, разделитель дробной части всегда точка.
- **Правки в `?dev=1`** живут до перезагрузки. Чтобы сохранить их, нужно скачать JSON и заменить конфиг.

## Чего нет и почему

- **Видео с телефона** — отдельно, не в репозитории.
- **Макет в Figma** (бонус) — дизайн собирался сразу в коде.
- **Реальный Android** — под рукой был только iPhone. FPS мерился в Chrome с замедлением CPU.
- **Старые iOS** не проверялись. Под iOS 15 стоят запасные варианты для `mask-image`, `color-mix()` и `roundRect()`. Подстройка панели под очень короткие экраны работает с iOS 16.
- **Автотесты в WebKit** — e2e идут в Chrome, Safari проверен вручную.
- **Lighthouse** — первая отрисовка мерится своим скриптом через `PerformanceObserver`.
- **Provably fair** — не входил в задание.
