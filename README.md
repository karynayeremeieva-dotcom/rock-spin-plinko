# Rock Spin · Plinko

[![CI](https://github.com/karynayeremeieva-dotcom/rock-spin-plinko/actions/workflows/ci.yml/badge.svg)](https://github.com/karynayeremeieva-dotcom/rock-spin-plinko/actions/workflows/ci.yml)

Страница игры Plinko для Telegram Mini App в стиле рок-клуба: концертная сцена с прожекторами, игровое поле внутри корпуса V-образной электрогитары в оранжево-синем санбёрсте, штырьки-струны, которые дрожат от удара шарика, светящиеся ячейки от холодного центра к раскалённым краям и пульт из матового стекла, подсвеченный тем же неоном.

- **Игра:** https://karynayeremeieva-dotcom.github.io/rock-spin-plinko/
- **В Telegram:** бот [@testagent1245363bot](https://t.me/testagent1245363bot), кнопка «Играть» или «Открыть приложение»
- **Второй дизайн, минималистичный:** та же ссылка с `?skin=minimal`, или «Меню → Дизайн»
- **Панель коэффициентов:** та же ссылка с `?dev=1`

Только фронтенд. Результат каждого шарика считает модуль-заглушка `src/api/plinko.ts`. Деньги демо: 1 000 RC при первом запуске.

## Запуск

```bash
npm ci
npm run dev          # http://localhost:5173
npm run check        # типы, ESLint, Prettier, актуальность таблиц, юнит-тесты
npm run build        # продакшн-сборка в dist/
npm run perf         # замеры: бандл, первая отрисовка, FPS (нужен Chrome)
npm run perf:soak    # 10 минут авто-режима: память, DOM, FPS
npm run e2e          # чек-лист приёмки в Chrome (или --url=… для выложенной версии)
npm run deploy       # проверки + сборка закоммиченного HEAD → ветка gh-pages
npm run gen:multipliers   # пересчитать таблицы 9–11 и 13–15 рядов
```

Нужен Node 20.19+. **CI** (`.github/workflows/ci.yml`) на каждый пуш и pull request прогоняет `npm run check`, сборку и `npm run e2e` в Chrome. Сайт на GitHub Pages публикуется из ветки `gh-pages` командой `npm run deploy`: она собирает закоммиченный код во временной копии репозитория и ничего не выкладывает, если не прошёл `npm run check`.

## Стек

React 18, TypeScript (strict, без `any`), Vite, Vitest, ESLint, Prettier. Доска рисуется на **Canvas 2D** без PixiJS, шарики не DOM-элементы. Других зависимостей во время работы нет, кроме двух самохостящихся шрифтов (Inter и Oswald).

## Как устроена игра

**Результат решается до анимации.** «Бросить» вызывает `play()`. Заглушка делает `rows` случайных выборов «влево/вправо» через `crypto.getRandomValues` (младший бит байта, 50/50 без перекоса), отвечает через 100–300 мс и возвращает путь, ячейку, коэффициент и выплату. UI не знает, как получен результат: чтобы подключить сервер, достаточно заменить `play` на запрос к API с тем же ответом.

**Анимация проигрывает известный путь.** Физики нет: она не гарантирует попадание в нужную ячейку. Шарик падает на верхний штырёк, затем прыгает параболами от штырька к штырьку ровно по `path` и падает в ячейку `bin`. Случайные мелочи (высота отскока, точка касания) меняют только вид полёта. Тест на 500 бросках при 8 и 16 рядах проверяет, что конечная точка всегда внутри нужной ячейки.

**Деньги только целые, в сотых.** `100 000 = 1 000.00 RC`. Коэффициент переводится в целые сотые (`5.6 → 560`), выплата = `floor(ставка × коэффициент / 100)`, без дробей ни на одном шаге. Ставка списывается синхронно в момент нажатия, ещё до ответа сервера, поэтому быстрые клики и авто-режим не могут увести баланс в минус. Выигрыш зачисляется, когда шарик долетает. Движок ведёт журнал: `начальный − ставки + выплаты = баланс`, это проверяется тестами.

**Рендер.** Штырьки один раз рисуются в отдельный слой, шарики, свечения и ячейки — готовые спрайты, поэтому кадр — это копирование картинок. Цикл отрисовки работает только пока что-то движется. Собственные часы доски сдвигаются не больше чем на 50 мс за кадр: когда вкладка свёрнута и браузер не даёт кадров, полёт стоит на месте и продолжается с того же места. Авто-режим на это время тоже ставится на паузу.

**Два дизайна доски.** Основной — корпус V-образной электрогитары, второй — классический минимализм: треугольник из чёрного обсидиана в зеркальной хромированной фаске со светом внутри, янтарным слева и синим справа. Гитара стоит на сцене под приглушёнными лучами прожекторов, треугольник — в графитовой темноте без фото (не чистый чёрный, чтобы не бить по глазам) с двумя мягкими пятнами света у полки, оранжевым и синим. Внутри треугольника своя начинка: хромированные шарики вместо пинов, без струн, вспышки цвета своей стороны, стеклянные ячейки. Ряды идут параллельно граням с одинаковым отступом, а ячейки растягиваются на всю полку. Переключаются в меню или параметром `?skin=guitar|minimal`, выбор сохраняется вместе с остальными настройками. У каждой картинки своя разметка поля и полки ячеек (`src/board/cabinet.ts`). Пирамида заново подгоняется под неё, тесты проверяют это для обоих дизайнов на всех числах рядов.

## Таблицы коэффициентов

Все 27 таблиц (ряды 8–16 × Low/Medium/High) лежат в `src/config/multipliers.json`. Таблицы для 8, 12 и 16 рядов взяты из задания без изменений. Таблицы для 9–11 и 13–15 рядов считает `scripts/generate-multipliers.mjs`:

1. **Форма.** Каждая таблица из задания превращается в кривую «логарифм коэффициента — расстояние от центра». Для N рядов кривые двух соседних таблиц (8 и 12 или 12 и 16) смешиваются с весом по N. В логарифмах кривая остаётся монотонной, а края растут геометрически.
2. **Масштаб.** Вся форма умножается на одно число так, чтобы RTP стал 99%.
3. **Округление.** Значения прилипают к «ценовой лестнице»: шаг 0.1 до 10×, целые до 100×, десятки выше, минимум 0.2×.
4. **Подгонка.** Округление сдвигает RTP, поэтому жадный проход двигает одну-две симметричные пары ячеек на шаг лестницы, сохраняя монотонность, пока RTP не станет 99% ± 0.05%.

Вероятность ячейки k: `C(N, k) / 2^N`, RTP = сумма вероятностей, умноженных на коэффициенты. RTP всех 27 таблиц — от 98.906% до 99.116%. `npm run check` падает, если JSON разошёлся со скриптом. Получившиеся значения близки к рыночным (например, 9 рядов High: `44 6.6 2.3 0.5 0.2 …`).

## Панель `?dev=1`

Кнопка DEV слева вверху. В панели:
- выбор рядов и риска, таблица с редактируемыми полями, по умолчанию правка симметричная;
- шанс каждой ячейки, её вклад в RTP и RTP таблицы пересчитываются на лету;
- предупреждения о несимметричности, неверных значениях и RTP вне 98.8–99.2%;
- «Применить» меняет таблицы в игре: на них работают заглушка сервера и доска;
- «Сбросить к конфигу» и «Скачать JSON» (файл в том же формате, что и `multipliers.json`);
- симуляция 100 000 бросков через тот же код, что у заглушки, показывает фактический RTP против теоретического. В браузере это занимает примерно 0.3–0.4 с.

## Telegram

Если страница открыта в Telegram (есть `window.Telegram.WebApp` с `initData`):
- вызывается `ready()` и `expand()`; на телефонах с Bot API 8.0+ — полноэкранный режим, при ошибке откат на `expand()`, ориентация фиксируется;
- `disableVerticalSwipes()`, чтобы жесты на доске не сворачивали приложение;
- цвет шапки и фона под палитру;
- `HapticFeedback`: удар при броске и старте авто, «успех» при выигрыше от 10×, «ошибка» при сбое сервера;
- подтверждение закрытия, пока шарики в полёте или идёт авто;
- системная кнопка «Назад» закрывает шторки;
- отступы учитывают `--tg-safe-area-inset-*` и `--tg-content-safe-area-inset-*`, высота — `--tg-viewport-stable-height`.

SDK подключается асинхронно, вне Telegram все вызовы молча пропускаются. Чтобы открыть игру как Mini App: в @BotFather → Mini Apps → Main App и Menu Button указать ссылку на GitHub Pages. Так игра проверена на iPhone в Telegram: открывается кнопкой меню бота, работают полный экран, отступы под вырез и кнопки Telegram, вибрация, системная кнопка «Назад» и подтверждение закрытия.

## Как я понял неоднозначные места

- **Блокировка рядов и риска** действует, пока хоть один шарик ждёт ответа или летит, а также всё время работы авто-режима. Ставку менять можно всегда, она применяется к следующим броскам.
- **Профит сессии авто** считается так: ставки — в момент броска, выплаты — в момент приземления. Это ровно изменение баланса, которое видит игрок. «Стоп при убытке» проверяется и перед каждым броском, и после каждого приземления. «Стоп при выигрыше ≥ Z×» срабатывает по одному шарику.
- **«Стоп» в авто** останавливает выпуск сразу, а уже летящие шарики долетают и платят. Счётчик профита продолжает учитывать их и после остановки.
- **Быстрые суммы 1/5/10/50** ставят ставку, а не прибавляют. `×2` ограничена балансом и максимумом 1 000 RC. `Max` = min(баланс, 1 000).
- **Перезагрузка во время полёта.** Результат уже решён «сервером», поэтому при сохранении летящие шарики считаются приземлившимися, а ставки, которые ещё ждут ответа, — возвращёнными. Деньги не теряются.
- **Сбой сервера.** Если `play` отклонён, ставка возвращается, появляется сообщение, авто-режим останавливается.
- **Сброс демо-баланса** доступен, только когда на доске пусто и авто остановлено. История при сбросе остаётся.
- **Большой выигрыш:** от 10× — «Крупный», от 50× — «Мега», от 250× — «Легендарный». Игру анимация не блокирует.
- **«Как играть»** сделано не отдельным модальным окном с картинками, а туром по настоящему экрану: всё затемняется, кроме нужных элементов, а рядом карточка с пояснением. На шаге броска летят бесплатные пробные шарики, баланс и история не меняются. На шаге риска переключатель работает прямо в туре, и видно, как меняются ячейки. Тур открывается сам при первом входе, повторно — из меню. Так игрок учится на тех же кнопках, которыми будет играть, а не на картинках, которые могут разойтись с интерфейсом.
- **История ставок** показывает последние 50 записей страницами по 10, фильтров нет: при одном виде ставки фильтровать нечего.
- **Звуки** синтезируются через Web Audio вместо коротких ogg/mp3 из раздела 6: ноль загрузок, гибкая громкость и защита от «треска» при 50 шариках (лимит частоты ударов и компрессор).
- **Числа:** RU — `1 000.00`, EN — `1,000.00`, десятичный разделитель всегда точка, как в задании. Шанс в подсказке — три значащие цифры (`0.00153%` для края 16 рядов).
- **Правки в `?dev=1`** живут до перезагрузки. Чтобы сохранить их навсегда, нужно скачать JSON и заменить файл конфига (так их увидит и будущий сервер).

## Тесты и проверки

**Юнит-тесты** (Vitest, 209 штук): деньги и выплаты, RTP и генератор таблиц, траектория и раскладка обоих дизайнов, условия авто-режима, хранилище, движок, интеграция с Telegram на подставном `WebApp`.

**E2E-тесты** — свой скрипт на puppeteer, а не Playwright: браузер не скачивается, используется установленный Chrome. `npm run e2e` собирает игру и прогоняет через интерфейс 22 проверки чек-листа 8.2: вёрстку без прокрутки на 360×640, 390×844 и 1440×900 для обоих дизайнов (доска 58% высоты на телефонах, кнопки шапки не вылезают), RU/EN, Пробел, сохранение баланса, рядов, истории и звука после перезагрузки, сходимость баланса, 300 быстрых кликов (баланс не уходит в минус), панель `?dev=1` (правка, пересчёт RTP, симуляция 100 000 бросков) и пустую консоль. Пункты 1, 4 и 6 проверяют 209 юнит-тестов, пункт 7 — `npm run perf`. Скрипт проходит и на локальной сборке, и на GitHub Pages (`--url=`).

**CI** на GitHub Actions на каждый пуш прогоняет `npm run check`, сборку и `npm run e2e`.

## Чего нет и почему

- **Видео с телефона** снимается отдельно, в репозитории его нет.
- **Макет в Figma** (бонус) не делался: дизайн собирался сразу в коде.
- **Реальный Android** не проверялся: под рукой был только iPhone, а замеры FPS сняты в Chrome с замедлением CPU (см. выше). В Telegram на iPhone игра проверена вручную. Логику интеграции с Telegram дополнительно покрывают тесты на подставном `WebApp`: вызовы при старте, откат с fullscreen на `expand()`, старые версии клиента, вибрация, подтверждение закрытия, кнопка «Назад».
- **Старые iOS** не проверялись. Игра рассчитана на Safari и Telegram с iOS 15: для `mask-image`, `color-mix()` и `roundRect()` стоят запасные варианты. Подстройка панели под очень короткие экраны сделана через container queries, они есть с iOS 16, на iOS 15 панель возьмёт обычный размер. Вручную проверено на iPhone с актуальной iOS — в Safari и в Telegram.
- **Прогона в WebKit** автотестами нет: e2e идут в Chrome, Safari проверялся вручную.
- **Lighthouse** не запускался, первая отрисовка мерится своим скриптом через `PerformanceObserver`.
- **Provably fair** (хеши раундов) не входил в задание и не сделан.
